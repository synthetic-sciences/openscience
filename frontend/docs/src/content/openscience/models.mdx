Choose **BYOK / Subscription** or **Ace** in **Customize → Models**. BYOK uses your own provider access; Ace uses the selected workspace's purchased Wallet through the Synthetic Sciences gateway. Local models use neither.

## Use Ace

Sign in from the Ace panel, select your workspace, and add Wallet funds or authorize Ace reloads. The model picker shows the available managed catalog and pricing for its actual upstream route.

Managed models currently use OpenRouter through the Synthetic Sciences gateway. Your own connected provider keys and eligible subscriptions use their separate direct routes; they are not charged to your Ace Wallet.

The model's context capacity and its pricing thresholds are different numbers. Open a model's options for its context limit, input/output rates, cache rates, and supported reasoning tiers. See [Pricing](/openscience/pricing).

## Connect a provider

Use **Customize → Models** or the CLI:

```bash
openscience keys add
openscience keys list
openscience models
```

You can sign in where a provider supports OAuth or save an API key locally. Environment variables work too:

```bash
export ANTHROPIC_API_KEY=sk-ant-...   # or OPENAI_API_KEY, GEMINI_API_KEY, ...
openscience
```

Anthropic, OpenAI, Google, OpenRouter, Groq, Mistral, xAI, Meta, DeepSeek, and other providers use this local flow. Access depends on your provider account. Shared workspace credentials can fill a missing connection without replacing a key or sign-in already saved on your device. See [Ace & connections](/openscience/gateway).

## Local models

OpenScience talks to OpenAI-compatible endpoints on your machine, including Ollama, LM Studio, llama.cpp, and vLLM:

```bash
openscience local add
openscience run --model ollama/llama3.1 "hello"
```

See **[Local models](/openscience/local-models)** for setup details.

## Mammouth API (custom provider)

Mammouth documents an [OpenAI-compatible chat endpoint](https://info.mammouth.ai/docs/api-quick-start/)
at `https://api.mammouth.ai/v1`. You can configure it without a native provider
integration. Merge this block into `openscience.json`; keep your actual key in
the `MAMMOUTH_API_KEY` environment variable, not the project file:

```json
{
  "provider": {
    "mammouth": {
      "name": "Mammouth",
      "npm": "@ai-sdk/openai-compatible",
      "options": {
        "baseURL": "https://api.mammouth.ai/v1",
        "apiKey": "{env:MAMMOUTH_API_KEY}"
      },
      "models": {
        "mammouth-recommended": {
          "name": "Mammouth Recommended",
          "tool_call": false,
          "reasoning": false
        }
      }
    }
  }
}
```

The `mammouth-recommended` alias follows Mammouth's current recommendation, so
the underlying model can change without editing this entry. For reproducible
runs, choose an exact model ID from Mammouth's [Model Explorer](https://model-explorer.mammouth.ai/).
Its [public catalog](https://api.mammouth.ai/public/models) supplies current IDs,
input/output limits and rates. OpenScience does **not** automatically import or
refresh that catalog; review the selected model's limits and pricing when using
a custom entry. Requests use your Mammouth account, not your Ace Wallet.

This conservative example is for chat: it does not advertise unverified tool
calling or reasoning controls. The public catalog does not declare those
capabilities, and this is not a verified agent/tool-model integration. Enable
capabilities only when the chosen Mammouth route's contract supports them.
Native Mammouth discovery remains a separate feature request.

## Choose a model per run

```bash
openscience run --model anthropic/claude-opus-5 --variant xhigh "Design the ablation study"
openscience run --model openai/gpt-5.6-terra --variant max "Review the analysis"
openscience run --model moonshotai/kimi-k3 "Implement the pipeline"
```

`--model <provider>/<model>` overrides the default for one run. `--variant` selects a provider-supported reasoning tier such as `minimal`, `high`, `xhigh`, or `max`.

## Reasoning and activity

The workspace shows every readable reasoning passage the provider sends, alongside
individual tool calls in their recorded order. Reasoning stays visible during
streaming, after completion, and when you reopen the session. There is no
Detailed/Compact selector. You can still open each tool's inputs and outputs.

Readable reasoning depends on the provider. OpenAI supplies
[reasoning summaries, not its private reasoning tokens](https://developers.openai.com/api/docs/guides/reasoning#reasoning-summaries).
OpenScience requests its most detailed available summary with `auto`; headings
inside that text come from the provider. OpenScience does not shorten those
passages or generate replacement summaries. Encrypted continuation metadata is
not readable text and does not create a blank reasoning row.

## Slow or stalled requests

The request status distinguishes local preparation, connecting, waiting for the first readable output, and receiving output. A connection delay can include network setup, gateway admission, and provider processing; it does not mean the model has been thinking for that whole interval. A stream can also remain open after its last output.

OpenScience stops a request that exceeds one of these default waits:

| Setting | Default | What it limits |
| --- | --- | --- |
| `connectTimeout` | 2 minutes | Waiting for response headers. |
| `idleTimeout` | 5 minutes | Waiting for the next response-body data, including transport keepalives. |
| `outputIdleTimeout` | 10 minutes | Waiting for new readable text, reasoning, or tool-call activity. Keepalives do not count. This timer pauses during local processing and tool execution. |
| `timeout` | No limit | Optional total request duration, even while output continues. |

There is no default total-generation limit. If your provider needs longer for private reasoning or a slow local model, merge an override into that provider's `options` in `openscience.json`. For example, this allows 20 minutes without readable output from your OpenRouter connection:

```json
{
  "provider": {
    "openrouter": {
      "options": {
        "outputIdleTimeout": 1200000
      }
    }
  }
}
```

Values are milliseconds. Set an individual option to `false` to disable that deadline; `timeout: false` does not disable the other three. Use the provider ID shown by `openscience models`, including the managed provider ID when configuring Ace.

Local overrides do not extend a gateway or provider's own limits. Ace also enforces server-side progress deadlines; disabling a desktop deadline cannot keep an idle managed request open indefinitely.

After a timeout, received output stays in your session. OpenScience does not automatically resend the model request: the provider may already have processed it, and a replacement can incur another charge. Review partial output and any completed tools before continuing yourself.

## Route ownership

| Route | Where requests go | Account used |
| --- | --- | --- |
| Provider key | Directly to that provider | Your provider account |
| Provider OAuth | Directly through that provider's supported sign-in | Your subscription or provider account |
| Workspace-shared provider key | Directly to that provider | The workspace's connected provider account |
| Ace | Synthetic Sciences gateway, then the catalog's declared upstream | The selected workspace's purchased Wallet |
| Local model | Your local endpoint | None |

## Key hygiene

Saved local credentials live in the per-user data root, not a project's `.openscience/` directory. Shared credentials use a separate encrypted, expiring overlay. General kernels receive a minimal environment, and credential-shaped secrets are redacted from output. Your local provider keys are not uploaded merely by signing in to Ace.
