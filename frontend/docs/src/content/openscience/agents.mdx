`research` is the single user-facing built-in agent. It owns the whole loop: literature review, hypothesis, code, experiments on real compute, analysis, and write-up. It loads narrow domain skills when they help and delegates genuinely independent work when it improves the result.

## Built-in roster

| Agent | Role | What it does |
| --- | --- | --- |
| `research` | Default | Scientific research across the full skill library — literature, data analysis, compute, and synthesis. |
| `plan` | Mode | Read-only planning. Edit tools are disabled except for plan files. |

Research has two canonical internal task profiles. They are hidden from the picker and selected by the kind of work, not by a user-facing persona:

| Profile | What it does |
| --- | --- |
| Explore | Read/search work: inspect a codebase, source set, or project state. |
| Execute | Implementation or computation using the active project permissions. |

Older domain and helper names remain as hidden compatibility profiles so existing config and sessions keep working; they are not the product roster. Run `openscience agent list` to inspect the complete registry on your install, including hidden compatibility and system profiles.

## Choose Research effort

```bash
# focused by default
openscience run "Fit the dispersion relation in data/spectra.csv"

# wider investigation when independent branches justify it
openscience run --effort ultra "Compare three defensible fitting approaches"
```

Normal and Ultra use the same Research harness. Ultra asks the model to investigate additional branches when they could change the result; it does not switch personas or impose a worker count. In the workspace, delegation posture is separate: Off, Low, Normal, and High guide how readily the lead parallelizes work, while Independence controls when the lead and workers ask clarifying questions. Runtime machine capacity queues concurrent workers rather than turning those controls into quotas. Plan mode is available when you want to agree on method, spend, or consequential actions before execution.

Custom agents remain available for teams with a deliberate specialized workflow. Set a custom agent with mode `primary` or `all` as `default_agent` in `openscience.json`; `subagent` profiles are reachable only by delegation.

## Create a custom agent

`openscience agent create` walks you through it interactively. The non-interactive form:

```bash
openscience agent create \
  --path .openscience \
  --description "Reviews analysis notebooks for data leakage and unsound statistics" \
  --mode subagent \
  --tools "read,grep,glob" \
  --model anthropic/claude-sonnet-5
```

| Flag | Use |
| --- | --- |
| `--path <dir>` | Where to write the definition; an `agent/` folder is created inside it. Omit to choose project or global interactively. |
| `--description <text>` | What the agent is for. A model expands this into the name, system prompt, and delegation description. |
| `--mode <all\|primary\|subagent>` | `primary`: leads a session. `subagent`: only reachable by delegation. `all`: both. |
| `--tools <tool[,tool...]>` | Allow-list of tools. Anything left off the list is disabled. |
| `--model <provider/model>` | Default model for this agent. |

The result is a Markdown file: YAML frontmatter (description, mode, tools) plus a body that is the system prompt. Edit it like any prose file.

## Tool restrictions

`--tools "read,grep,glob"` produces a read-only agent that cannot be tricked into editing files. The available tools are `bash`, `read`, `write`, `edit`, `list`, `glob`, `grep`, `webfetch`, `task`, `todowrite`, and `todoread` — run `openscience agent create --help` for the list on your version.

## Where agents live

```text
.openscience/agent/             # project-scoped
~/.config/openscience/agent/    # user-global
<bundled>                       # ships with OpenScience
```

Resolution is project-local, then user-global, then built-in.
