OpenScience is open source under Apache-2.0, and the agent runs locally. Projects, sessions, settings, results, and saved credentials stay in the selected data root.

## Permissions and containment

The permission system decides whether the agent may take an action. It is not an isolation boundary by itself.

New installs default to **Ask risky**: contained reversible work proceeds, while external, costly, or hard-to-reverse actions require approval. macOS uses Seatbelt and Linux uses bubblewrap when available. Use **Research tools → Action approval** to choose a stricter or broader mode, and verify the boundary with:

```bash
openscience sandbox
openscience sandbox test
```

The sandbox is not a full VM. Run actively hostile code inside a dedicated container or VM.

## Credential storage

| Surface | Where | Notes |
| --- | --- | --- |
| Provider keys and OAuth | `<data-root>/auth.json` | Encrypted local provider access; requests go directly to the provider. |
| Connector credentials | `<data-root>/credentials.json` | Encrypted local service access. |
| Compute credentials | Local compute store | Injected only by the selected compute adapter. |
| Native binary | `~/.openscience/bin/openscience` | Used by the curl installer. |

The data root defaults to `~/.openscience` and can be moved from **Customize → Storage** or with `OPENSCIENCE_DATA_DIR`. Global configuration uses `OPENSCIENCE_CONFIG_DIR` or its XDG default. Run `openscience debug paths` to inspect the resolved locations.

## Subprocess boundaries

Approved shell tools receive a sanitized environment. Supported user-owned model and service credentials may be injected for the task, while compute control-plane keys are added only by the selected adapter. Python and R kernels receive a minimal runtime and locale environment. Known credential patterns are redacted before tool output is written into a session.

The interactive terminal is a user-owned shell, not an agent subprocess, so treat it like any terminal you launch yourself.

## Server mode

The local server binds to `127.0.0.1` and enforces Host and Origin allowlists. If you deliberately expose it through a tunnel or reverse proxy, securing that exposure is your responsibility. Set `OPENSCIENCE_AUTH_TOKEN` to require a bearer token for network requests.

## What can leave your machine

- Prompts and responses sent to the model provider you selected.
- Requests made to scientific services, MCP servers, publishing targets, or compute providers you connect or approve.
- Files explicitly uploaded by one of those approved tools.

OpenScience does not upload session traces to a product control plane.

## Reporting a vulnerability

Use the GitHub Security Advisory [Report a Vulnerability](https://github.com/synthetic-sciences/openscience/security/advisories/new) form rather than a public issue.
