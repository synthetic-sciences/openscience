Run a shell command in the session workspace. Use `workdir` instead of changing directories inside the command.

Use Bash for builds, tests, package managers, Git, system utilities, and scripts. Prefer the dedicated file tools for reading, searching, creating, or editing files. Do not use shell redirection, `echo`, or `cat` to write files when a dedicated tool can perform the operation safely.

Quote paths containing spaces. The `command` field is required; `timeout` is optional. Output beyond ${maxLines} lines or ${maxBytes} bytes is saved automatically, so do not add `head` or `tail` merely to limit output. Give each call a concise 5–10 word description.

Issue independent Bash calls together so they can run in parallel. Combine dependent operations with `&&` only when the later operation must not run after failure.

Git and GitHub safety:
- Commit, push, or create a pull request only when the user explicitly requests it.
- Before committing, inspect status, diff, and recent log; stage only the intended paths.
- Never change Git configuration, bypass hooks, force-push, use interactive Git, or run a destructive reset/checkout without explicit authorization.
- Do not amend a pushed commit. Never push directly to `main` or `master`.
- For a requested pull request, inspect the complete branch diff against its base, use `gh`, create at most one PR, and return its URL.
