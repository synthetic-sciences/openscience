Delegate one bounded, independent unit of work when parallel investigation or execution will
materially improve the result.

Internal profiles:
{agents}

Choose the profile by work type, not scientific domain:
- `explore` finds and reads relevant code, files, or sources.
- `execute` performs a bounded implementation, analysis, or computation.
- `review` checks an observable result when the cost of an error justifies an independent pass.

Domain expertise comes from lazy skills. Do not invent a biology, physics, literature, writing,
statistics, or ML persona; give the selected profile the exact task and let it load a relevant
skill only when useful.

Research effort controls optional parallelism:
- Normal: default to zero children; at most two can run concurrently.
- Ultra: use a wider investigation only when branches are genuinely independent; at most four
  can run concurrently.

Rules:
1. Fan-out is shallow. A child cannot create more child tasks.
2. Do not delegate sequential work, a small known-file edit, or a second opinion by ceremony.
3. Retrieve a source set once and share it; never launch duplicate literature searches.
4. The lead Research agent owns synthesis and verification. Treat child output as evidence, not
   authority, and do not let an optional failed child block a usable result.
5. Continue a child only with its `session_id`. Otherwise give a self-contained prompt with the
   objective, relevant context, allowed actions, and the useful return shape.
