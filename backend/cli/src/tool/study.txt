Run a research study: an autoresearch loop that hill-climbs one metric over many runs. You own the science (ideas, code, verdicts); OpenScience owns the clock (metrics, run endings, kill criteria, budget) and wakes this session with a "Study update" when there is news. Load the autoresearch skill for the method.

Actions (one per call):
- create: name, purpose, metric, direction, optional target/concurrency/kill_criteria/budget/review. Once per session, after the plan is agreed.
- status: baseline, best, queue, live runs, budget, lessons.
- propose: ideas[] with title, description, why, ev (metric units × confidence), config; baseline first with priority 1000.
- start: idea_id + command (the script must log the metric through openscience_track or wandb). One run per idea, never two.
- record: run_id, kept, analysis, optional conclusion/lessons; baseline:true marks the reference run.
- drop: idea_id + reason.
- conclude: conclusion (what was learned, best configuration, what remains open).

Rules: exactly one run per idea; record every ended run; keep up to concurrency runs live; read metrics with the experiments tool; never ask whether to continue while budget remains.
